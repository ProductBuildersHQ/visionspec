# Spec Kit plugins from visionspec

This directory packages visionspec workflow families as [GitHub Spec Kit](https://github.com/github/spec-kit)
plugins, using Spec Kit's official component formats:

| Component | Path | Origin |
|-----------|------|--------|
| `one-way-door` extension | `extensions/one-way-door/` | Generated from the `aws-one-way-door` family |
| `one-way-door-engineering` extension | `extensions/one-way-door-engineering/` | Generated from the `aws-one-way-door` family |
| `one-way-door-chain` workflow | `workflows/one-way-door-chain/` | Generated from the `aws-one-way-door` family's execution sequence + review gates |
| `risk-adjusted` workflow | `workflows/risk-adjusted/` | Hand-authored |
| `product-management` bundle | `bundles/product-management/` | Hand-authored |
| `product-builders` bundle | `bundles/product-builders/` | Hand-authored |
| Catalogs | `catalog/*.json` | Hand-maintained (updated per release) |

## What these do

Risk-adjusted delivery triages every piece of work through the one-way-door /
two-way-door test (reversibility and blast radius) and routes it to the
right amount of ceremony:

- **Bug** → Spec Kit's built-in bug pipeline (`/speckit.bug.assess` → `.fix` → `.test`)
- **Feature** (reversible two-way door) → the core Spec-Driven Development flow
  (`/speckit.specify` → `.plan` → `.tasks` → `.implement`)
- **Initiative** (hard-to-reverse one-way door) → the Amazon Working Backwards
  chain from the `one-way-door` extension: press release → FAQ → PR/FAQ review →
  optional MRD → PRD → six-pager decision meeting (mandatory human gate) → UXD,
  then the `one-way-door-engineering` add-on (TRD → TPD → IRD) or a handoff to
  `/speckit.specify` — carrying the PRD and UXD in as its description, so it
  synthesizes spec-kit's own spec.md rather than starting from a blank one

The product extension stops at requirements (UXD included — user-experience
requirements belong to the product team); the engineering add-on carries the
chain through the technical specs. Install one or both via the role bundles.

Two workflows are available, for two different situations:

- **`risk-adjusted`** (hand-authored) — you don't yet know how much ceremony
  the work needs. It triages first (bug / feature / initiative) and routes
  into the right chain.
- **`one-way-door-chain`** (generated) — you already know this is a
  one-way-door initiative and want the full press → faq → … → ird sequence
  run end to end, with review gates exactly where the family declares them
  and optional specs (e.g. the MRD deepening) exposed as `include_<spec>`
  inputs rather than always run. It's the data-driven counterpart to
  `risk-adjusted`'s `initiative` branch — regenerated automatically whenever
  the source family's sequence or gates change, so it never drifts from the
  extension it drives.

## Install

From a Spec Kit project (`specify init ...`):

```bash
# Extensions (local paths work for development; release zips for consumption)
specify extension add one-way-door --dev <repo>/speckit/extensions/one-way-door
specify extension add one-way-door-engineering --dev <repo>/speckit/extensions/one-way-door-engineering

# Triage workflow
specify workflow add --dev <repo>/speckit/workflows/risk-adjusted
specify workflow run risk-adjusted
```

Or via catalogs and bundles:

```bash
specify extension catalog add https://raw.githubusercontent.com/ProductBuildersHQ/visionspec/main/speckit/catalog/extensions.json --install-allowed
specify workflow catalog add https://raw.githubusercontent.com/ProductBuildersHQ/visionspec/main/speckit/catalog/workflows.json
specify bundle install <repo>/speckit/bundles/product-builders
```

## Regenerating

The `extensions/` directories are **generated — do not edit**. Each file
carries a `Code generated by visionspec speckit export; DO NOT EDIT` header.
To change them, change the source workflow family under
`pkg/workflows/default/aws-one-way-door/` (or the exporter in `pkg/speckit/`)
and regenerate:

```bash
go run ./cmd/visionspec speckit export aws-one-way-door -o speckit
```

CI enforces sync via `visionspec speckit export --check` (and the
`TestCommittedArtifactsInSync` test in `pkg/speckit`).

## Releasing

Tag `speckit-vX.Y.Z` to trigger `.github/workflows/release-speckit.yaml`,
which zips each extension (manifest at zip root) and bundle, checksums them,
and uploads them as release assets. After a release, update the
`download_url`/`sha256` values in `catalog/*.json`. The same values back any
future submission to Spec Kit's community catalogs.
