# prism-sync

Copies canonical templates and rubrics from
[grokify/prism-roadmap](https://github.com/grokify/prism-roadmap) into
this repo's embedded workflow catalog (`pkg/workflows/default/`). This is a
physical copy, not a Go import: the catalog is `//go:embed`-based
(filesystem-free loading at runtime), so the files have to actually live in
this repo's tree — a versioned dependency alone can't put markdown/YAML
where `go:embed` needs it.

It's a separate nested module (its own `go.mod`) specifically so
`prism-roadmap`'s dependency tree never enters the main module graph — this
is a one-time-per-run sync tool, not a runtime dependency of anything else
in this repo.

Every synced file carries a `Code generated by prism-sync; DO NOT EDIT`
provenance header naming its `prism-roadmap@<version>` source. **Do not
hand-edit synced files** — change the upstream in prism-roadmap, release it,
bump the require here, and re-run the sync. To change *which* files sync
where, edit `manifest.yaml`.

## What is synced

See `manifest.yaml` for the authoritative mapping. Currently:

| Workflow family | Templates & rubrics |
|-----------------|---------------------|
| `enterprise` | bmc, opportunity-spec |
| `continuous-discovery` | ost, assumption-map, discovery-snapshot, experience-map |
| `v2mom` | vision, values, methods, obstacles, measures, alignment, summary |

## Running it

Synced from a tagged prism-roadmap release (`v0.18.0`), pinned in this
module's `go.mod` — no `replace` directive, so this runs from a fresh clone
or in CI with no local checkout required.

```bash
# Check for drift without writing anything (safe for CI)
go run -C tools/prism-sync . -check

# Actually sync (writes updated copies + provenance headers)
go run -C tools/prism-sync .
```

Run the sync whenever you bump the `prism-roadmap` require to pick up
upstream template/rubric changes, or add/remove entries in `manifest.yaml`.

## Upgrading the source version

1. Bump the require: `go get -C tools/prism-sync github.com/grokify/prism-roadmap@vX.Y.Z`
2. Re-sync: `go run -C tools/prism-sync .`
3. Verify: `go run -C tools/prism-sync . -check` and `go test ./...`
4. Commit the go.mod/go.sum bump together with the re-synced catalog files.

## Remaining automation

The one open item is wiring a scheduled GitHub Actions job (weekly cron)
that runs `go run -C tools/prism-sync . -check` and fails on drift. Now that
the tool resolves from a tagged release, that check can actually pass from a
fresh checkout — so it's safe to automate (unlike the earlier
replace-directive era, when a `-check` cron would have been permanently red).
