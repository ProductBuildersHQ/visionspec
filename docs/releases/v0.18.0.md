# Release v0.18.0

**Release Date:** 2026-09-26

This release adds a second distribution path for VisionSpec's methodology
catalog: alongside the existing `visionspec init`/CLI/MCP authoring flow, a
workflow family can now be exported as native
[GitHub Spec Kit](https://github.com/github/spec-kit) extensions, workflows,
and bundles, for use in any Spec Kit project — VisionSpec-authored or not.

## Highlights

- **`visionspec speckit export`**: packages a workflow family as Spec Kit
  extensions. The first family shipped, `aws-one-way-door`, splits by spec
  category into a `one-way-door` product extension (press, faq, mrd, prd,
  narrative-6p, uxd) and a `one-way-door-engineering` add-on (trd, tpd, ird).
  Each spec type becomes a Spec Kit command that authors its document from
  the family's template and self-evaluates against the family's rubric
  before reporting done
- **`risk-adjusted` triage workflow**: a hand-authored front door that
  routes any piece of work by reversibility — a bug goes to Spec Kit's
  built-in bug pipeline, a reversible two-way-door feature goes to the core
  `specify`/`plan`/`tasks`/`implement` flow, and a hard-to-reverse
  initiative gets the full one-way-door chain with its review gates. A
  generated `one-way-door-chain` workflow, compiled straight from the
  family's execution sequence and review gates, covers the case where the
  ceremony decision is already made
- **Role bundles and catalogs**: `product-management` (the product
  extension + `risk-adjusted`) and `product-builders` (adds the engineering
  extension) let a team install the whole methodology with one command,
  with catalog JSON files for eventual community-catalog discovery
- **Spec type ids are now a documented, stable contract**: `Execution.Sequence`
  entries were already the loader-derived template-filename stem; this
  makes that node-identity contract explicit and adds a matching
  `ReviewGate.StepID()`, so the exporter (and any future consumer) has a
  stable identifier to rely on instead of reinventing one
- RMI-030 complete: the spec judge now sees the layered
  class/blocking/evaluation rubric taxonomy introduced in v0.16.0/v0.17.0

## Added

- `pkg/speckit`: the exporter package — `BuildExtensions` splits a family's
  execution sequence by spec category into product/engineering extensions;
  `BuildWorkflow` compiles a family's full sequence and review gates into a
  single workflow.yml
- `visionspec speckit export [workflow] [-o dir] [--check]` CLI command;
  `--check` verifies committed artifacts still match the generator instead
  of writing, for CI
- `speckit/`: the generated `one-way-door` and `one-way-door-engineering`
  extensions and `one-way-door-chain` workflow, the hand-authored
  `risk-adjusted` workflow, the `product-management`/`product-builders`
  bundles, and their component catalogs — every generated file carries a
  `Code generated ...; DO NOT EDIT` provenance header, enforced by
  `--check` and a repo-level drift test
- `ReviewGate.ID`/`StepID()` on `pkg/workflow.ReviewGate`, defaulting to a
  kebab-cased `Action` when no explicit id is set

## Documentation

  the primary path with `specify workflow run` as the unattended/CI
  alternative
- [`speckit/README.md`](https://github.com/ProductBuildersHQ/visionspec/blob/main/speckit/README.md):

- Every methodology framework page (AWS, Google, Stripe, Big Tech, Shape
  Up, Continuous Discovery, Lean Startup, Design Thinking, JTBD,
  OpportunitySpec) now explicitly discloses it is ProductBuildersHQ's
  independent interpretation, not official material from the named company
  or practitioner
- RMI-030 marked complete in `ROADMAP.md`

## Infrastructure

- Tag-triggered `release-speckit.yaml` GitHub Actions workflow: verifies
  the generator drift gate, zips each extension and bundle with its
  manifest at the zip root, checksums everything, and publishes a GitHub
  release

## Compatibility

Fully additive — no breaking changes. `pkg/workflow.ReviewGate.ID` is a new
`omitempty` field; existing profiles and exported output are unaffected.

## Installation

```bash
go get github.com/ProductBuildersHQ/visionspec@v0.18.0
```
